# QUE — инструкции для работы над проектом

## О проекте

QUE — новостной портал для сотрудников Центрального банка Российской Федерации. Его задача — помогать сотрудникам быстро находить и читать актуальные новости. Интерфейс должен быть современным, качественным и удобным для повседневной работы.

Проект находится на начальном этапе. Текущий стек frontend указан ниже;
стек backend, СУБД и команды разработки ещё не зафиксированы. Не считайте
неопределённые решения выбранными без подтверждения в репозитории или от пользователя.

## Текущее состояние репозитория

- Принята структура `frontend/`, `backend/`, `db/` и корневой `compose.yaml`.
- Frontend: React + TypeScript, Vite, Tailwind CSS 4, Framer Motion; настроена структура shadcn/ui.
- `@/` указывает на `frontend/src/`; UI-компоненты — `frontend/src/components/ui/`, общие стили — `frontend/src/styles/globals.css`.
- Запуск локальной разработки: `docker compose up --build`, адрес — `http://localhost:5173`.
- Проверка конфигурации: `docker compose config --quiet`.
- Проверка TypeScript и сборка: `docker compose run --rm --no-deps frontend npm run build`.
- Только проверка TypeScript: `docker compose run --rm --no-deps frontend npm run typecheck`.
- Серверная сборка и запуск: `docker compose -f compose.deploy.yaml up -d --build --wait`; nginx отдаёт собранный frontend на порту `QUE_HTTP_PORT` (по умолчанию 8080), с healthcheck и автоматическим перезапуском.
- Изменения сохраняются в `main`. Prod-стенд `84.252.132.136:8080`, каталог `/home/ganbei/que`, обновляется из `https://github.com/notglebatall/que.git` через `git pull --ff-only origin main`, затем пересобирается Docker Compose. Отдельного dev-стенда нет. Не копируйте исходники на стенд вне Git.
- При наличии локального Node.js: команды `npm ci`, `npm run dev`, `npm run build` выполняются из `frontend/`.
- Backend и db пока содержат только заготовки; их стек и технологии не выбраны.
- Текущий UI — светлая схема главной: неподвижная сетка CategorySelector сверху, пять рубрик (Экономика, Политика, Финансы, Технологии, Прочее), отдельное начальное состояние «Все новости» и область вертикальной ленты. Карточки сохраняют размер и положение при выборе; сетка адаптируется к экрану (6/3/2 столбца). Карточки новостей и дополнительные функции пока не разрабатываются.

## Принципы продукта и интерфейса

- Основной язык интерфейса — русский. Пишите понятно и лаконично, в профессиональном и нейтральном тоне.
- Отдавайте приоритет содержанию: обеспечивайте читаемую типографику, ясную иерархию, удобную навигацию и аккуратное представление новостей.
- Создавайте цельный визуальный язык: согласованные цвета, отступы, компоненты и состояния элементов. Учитывайте существующий дизайн, если он появится.
- Делайте интерфейс адаптивным для разных размеров экранов. Проверяйте состояние загрузки, пустые результаты и ошибки там, где они применимы.
- Используйте семантическую разметку, доступные названия элементов, видимый фокус клавиатуры и достаточный контраст. Не полагайтесь только на цвет для передачи смысла.
- Не выдавайте демонстрационные новости, изображения, статистику и данные пользователей за реальные. Явно обозначайте примеры и заглушки.
- Не предполагайте наличие утверждённого брендбука, логотипов или других официальных материалов. Следуйте предоставленным материалам и требованиям, когда они появятся.

## Работа с кодом

- Перед изменениями изучайте относящийся к задаче код, документацию и принятые в проекте соглашения. Сохраняйте существующие паттерны, если нет причины их менять.
- Выполняйте изменения в пределах задачи; избегайте несвязанных переделок и новых зависимостей без необходимости.
- Выносите повторяющиеся элементы интерфейса в переиспользуемые компоненты, когда это упрощает поддержку, и не усложняйте архитектуру заранее.
- Не добавляйте секреты, реальные персональные данные или внутренние данные организации в репозиторий, примеры и логи. Используйте тестовые данные и переменные окружения по принятым в проекте правилам.
- Не придумывайте требования к авторизации, интеграциям, размещению или доступу к данным. Уточняйте их, если они необходимы для реализации.

## Проверка изменений

- Запускайте проверки, относящиеся к изменению, используя команды, определённые в проекте. Если команд или тестов пока нет, сообщайте об этом в результате работы.
- Для изменений интерфейса проверяйте основные сценарии, адаптивность и доступность в пределах доступных средств.
- При появлении стека и инструментов обновите этот файл конкретными командами запуска и проверки, а также существенными соглашениями проекта.
